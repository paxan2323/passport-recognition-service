# Дообучение распознавалки паспортов

Пайплайн для улучшения кастомной CRNN-сети docreader (None-VGG-BiLSTM-CTC,
grayscale, imgH=64, алфавит из `custom_example.yaml`). Цель — повысить
качество на реальных дефектах (блики, перспектива, расфокус) и на адресных
полях (прописка: край/область, район, город, ПГТ, мкр, улица, дом/кв).

## Установка

```bash
.venv\Scripts\python.exe -m pip install -r requirements-training.txt
```

Трейнер EasyOCR склонирован в `training/EasyOCR/` и локально пропатчен под
свежие torch/pandas и CPU/Windows (см. «Патчи трейнера» ниже).

## Пайплайн

### 1. Синтетика (`synth_generator.py`)

Генерирует кропы полей на процедурной защитной сетке с аугментациями под
наши дефекты. Алфавит меток валидируется по сети. Адресные поля включены
(регион, район, нас. пункт, мкр, улица, дом/корп/кв) — их можно расширять
списками в начале файла.

```bash
python training\synth_generator.py --count 100000 --out training\data\synth_v1
```

Дополнительные моноширинные шрифты с кириллицей — в `training\fonts\*.ttf`.

### 2. Реальные данные с MRZ-авторазметкой (`collect_dataset.py`)

Прогоняет папку фото через пайплайн. Поля, подтверждённые чексуммами MRZ,
сохраняются как готовые пары «кроп → текст». Неподтверждённые и поля без
эталона (место рождения, кем выдан) уходят в `hard/` на ручную сверку.

```bash
python training\collect_dataset.py D:\photos --out training\data\real --recursive
```

Инкрементально: повторный запуск обрабатывает только новые фото.
`hard/review.tsv` — очередь ручной проверки (кроп + подсказка OCR).

### 3. Подготовка данных трейнера (`prepare_trainer_data.py`)

Сливает датасеты в `EasyOCR/trainer/all_data/{ru_train,ru_val}`
(images + labels.csv), фильтруя метки по алфавиту сети.

```bash
python training\prepare_trainer_data.py training\data\synth_v1 training\data\real
```

### 4. Обучение (`train_recognizer.py`)

```bash
python training\train_recognizer.py --smoke   # проверка пайплайна (CPU, ~2 мин)
python training\train_recognizer.py           # полное обучение
```

Дообучает от `custom_example.pth` (FT=True). Алфавит берётся из
`custom_example.yaml` — порядок символов совпадает с предобученной головой
(num_class=208). Чекпоинты: `EasyOCR/trainer/saved_models/ru_passport/`.

**Нужен GPU.** На CPU одна итерation batch=32 ≈ 1.5 с → 30k итераций ≈ 12 ч.
На NVIDIA 8+ ГБ — вечер. Модель всего 15 МБ.

### 5. Оценка и подмена

```bash
python training\eval_recognizer.py training\data\synth_v1 --limit 1000
```

Сравнить кандидата со старой сетью (CER + полное совпадение). Если лучше:

```bash
# backup!
copy %USERPROFILE%\.cache\docreader\models\easyocr\model\custom_example.pth ^
     custom_example.backup.pth
copy training\EasyOCR\trainer\saved_models\ru_passport\best_accuracy.pth ^
     %USERPROFILE%\.cache\docreader\models\easyocr\model\custom_example.pth
```

docreader подхватит новую сеть без изменений кода (конфиг параметризован).

## Результаты обучения (GPU, RTX 4070)

Проведено на изолированном `training/.venv-gpu` (torch 2.6.0+cu124),
рабочий `.venv` не тронут.

**Распознавалка** — дообучение от `custom_example.pth`, 8000 итераций,
100k синтетики. Замер на held-out `synth_v1` (seed 1, НЕ входил в обучение):

| Метрика | Исходная сеть | Дообученная | Дообученная + сортировка |
|---|---|---|---|
| Полное совпадение | 60.2% | 74.8% | **76.0%** |
| CER | 16.3% | 5.5% | **3.8%** |

Дообученная сеть подставлена в `~/.cache/docreader/models/easyocr/model/
custom_example.pth` (оригинал → `custom_example.backup.pth`). Откат:
скопировать backup обратно.

«Сортировка» — `postprocess/sorted_ocr.py` (SortedOcrEngine): фрагменты
readtext склеиваются в порядке чтения (строки → слева-направо), а не в
порядке выдачи EasyOCR. Это чинит развал числовых полей
(`17.04.1985` → было `17 1985 04.`). Подключено в `build_reader`;
в eval — путь по умолчанию (`--unsorted` для старого поведения).

**Прямое распознавание без детектора строк (04.07.2026)** — крупнейший
прирост за всю работу: кропы зон почти всегда однострочные, и главным
источником ошибок был внутренний детектор строк EasyOCR (пустые ответы,
дробление дат), а не распознающая сеть. `SortedOcrEngine` теперь сначала
подаёт кроп целиком в `reader.recognize()` (одной строкой, без детекции),
и только при низкой уверенности (<0.55, многострочные зоны) падает в
readtext+сортировку. На synth_v1: **78.0% → 98.2%, CER 3.3% → 0.5%**
без переобучения.

**Реальный бенчмарк** — `build_real_benchmark.py`: 300 MRZ-подтверждённых
паспортов из S3 переразмечаются свежим пайплайном в `data/real_bench` и
исключаются из обучающего набора. `swap_recognizer.py` принимает решение
о подмене по нему (синтетика — fallback). Инцидент 04.07: дообучение на
данных, собранных с мягким порогом сверки ФИО (75), дало регрессию —
порог поднят до 92 (`postprocess/passport.py`), загрязнённые ФИО-пары
вычищены, guard-порог ужесточён до 1.15x, бэкапы версионируются.

**MRZ чексумм-коррекция** — `mrz.try_fix_digits`: одиночная спутанная
цифра восстанавливается перебором частых OCR-путаниц; mod-10 чексумма
неоднозначна, поэтому спорные случаи разрешаются только совпадением с
независимым чтением визуальной зоны (`number_hint`).

**Замеры 05.07.2026 (real_bench):**
- Полный пайплайн с MRZ-арбитражом на MRZ-валидных паспортах: **99.0%**
  полевой точности (цифровые поля 100%, хвост — ФИО). Оговорка: это
  MRZ-валидная подвыборка; на потоке без читаемой MRZ работает только
  визуальный путь (~88% на уровне кропов).
- Экстракция значений из шума (`normalize`, `extract=True`) — сделано,
  эффект +0.5пп (в осн. нормализация пола); безопасно, остаётся.
- A/B `crop_shrink=0.08` — **хуже** (99.0→97.4, отчества 94.5→83.3):
  рамки на реале местами и так тесные. Дефолт 0.0, не включать.
- Арбитраж ФИО: при конфликте с надёжной MRZ (чексуммы строки 2 сошлись)
  теперь берётся MRZ-транслитерация, не шумная визуальная зона.
  Эффект: end-to-end **99.0% → 99.3%** (отчество 94.5→96.6, имя 96.3→97.8).
- Инструменты: `eval_field_level.py` (покроповый полевой замер),
  `eval_pipeline_bench.py` (живой A/B полного пайплайна по bench_keys).

**Детектор прописки** — yolo11n-obb, 100 эпох, 3000 train / 300 val
(независимый seed). На held-out val: P≈1.0, R≈1.0, mAP50 0.995,
mAP50-95 0.993 (по всем 4 классам). Веса →
`~/.cache/docreader/models/regpage_obb.pt`. End-to-end проверен
(`verify_registration.py`): зоны локализуются точно даже при перспективе,
штамп исключается, адрес/дата/орган собираются.

> Метрики — на синтетике (домен обучения). Для продакшена нужны реальные
> данные: реальные кропы полей (собираются `collect_dataset.py` через
> MRZ-авторазметку) и несколько сотен реальных страниц регистрации.

## Детекция прописки (страница регистрации)

Распознавалка выше учит читать адресный текст, но детектор `passport.pt`
не размечает зоны страницы регистрации. Для них — отдельный YOLO-OBB
детектор, обучаемый на синтетике с автоматической разметкой.

### 1. Синтетика страниц (`regpage_generator.py`)

Рендерит страницу «Место жительства» со штампами и адресами, зная
координаты каждого поля → OBB-разметка без ручной аннотации.
Аугментация двигает и картинку, и рамки одним преобразованием.

```bash
python training\regpage_generator.py --count 3000 --out training\data\regpage
```

Классы: `reg_authority`, `reg_date`, `reg_address` (строки), `reg_stamp`.
Проверить разметку: `python training\_debug_overlay.py <dataset_dir> <img_name>`.

### 2. Обучение детектора (`train_detector.py`)

```bash
python training\train_detector.py --smoke --data training\data\regpage_preview\data.yaml
python training\train_detector.py --epochs 100        # полное (GPU)
```

Дообучает `yolo11n-obb`. Веса: `training/runs/regpage/weights/best.pt`.

Генератор аугментирует поворотом 0/90/180/270° (штамп на фото часто
повёрнут) — рамки поворачиваются вместе с изображением.

### 3. Использование (`postprocess/registration_detector.py`)

```python
from postprocess.registration_detector import RegistrationDetectorReader
reader = RegistrationDetectorReader("training/runs/regpage/weights/best.pt")
res = reader.read(page_bgr, auto_rotate=True)   # перебор 4 поворотов
print(res.as_dict())   # region/city/street после словарной коррекции
```

- `auto_rotate` — перебор 4 поворотов, выбор по суммарной уверенности
  детекций (штамп на реальном фото повёрнут — без этого детектор
  промахивается);
- адрес чистится гейзеттиром (`postprocess/gazetteer.py`): регион/город
  фаззи-сверяются со справочником hflabs/city, тип улицы нормализуется,
  мусорные строки отбрасываются;
- дата понимает формат прописью («14 июля 2015 г.»,
  `normalize.normalize_any_date`).

Без хардкода под регионы (в отличие от эвристического
`postprocess/registration.py`, который остаётся фолбэком).

**Реальные данные.** Синтетика бутстрапит детектор; для продакшена нужны
несколько сотен реальных страниц регистрации (разметка в CVAT/roboflow
в формат YOLO-OBB), синтетика остаётся как аугментация.

## Постобработка адресов (`postprocess/`)

- `sorted_ocr.py` — `SortedOcrEngine`: склейка фрагментов readtext в
  порядке чтения (чинит развал числовых полей). Подключён в `build_reader`.
- `gazetteer.py` — фаззи-коррекция регион/город по hflabs/city
  (`data/city.csv`), нормализация типов улиц/нас. пунктов.
- `normalize.py` — `normalize_any_date` (числовые + прописью даты).

## Патчи трейнера (`EasyOCR/trainer/`)

Вендорный клон изменён локально:
- `dataset.py`: `_accumulate` из `itertools` (убран из torch>=2);
  `.next()` → `next()` (старый DataLoader API).
- `train.py`: `torch.load(..., map_location=device)` (модель сохранена на
  CUDA); `prefetch_factor` только при `workers>0` (Windows/CPU).

При обновлении клона патчи применить заново.
